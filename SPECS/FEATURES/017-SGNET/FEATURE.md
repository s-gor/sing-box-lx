# SG-Net

## Назначение

SG-Net — клиентский транспорт SG-Net/1 для sing-box-lx. Он позволяет TUN/маршрутизатору sing-box отправлять TCP и UDP через SG-Net Server без отдельного локального SOCKS-прокси и без отдельного процесса sgnet-client.

Фича совместима с существующим SG-Net Server: внедрение нативного клиента не меняет SG-Net/1 wire protocol и не требует изменения сервера.

## Контролируемые параметры

Пользовательский тип outbound: `sgnet`.

Build-tag: `with_sgnet`. Без него SG-Net отсутствует из поставки и не меняет поведение upstream.

Конфигурация SG-Net содержит:

- `server`: адрес SG-Net Server;
- `server_port`: TCP-порт сервера;
- `server_name`: SNI и имя для проверки сертификата TLS;
- `device_id`: идентификатор устройства;
- `secret`: per-device секрет аутентификации;
- стандартный блок `tls`: TLS включён обязательно; небезопасное отключение проверки сертификата SG-Net не поддерживает.

Секрет является чувствительным параметром и не должен попадать в журналы.

## Входы

Фича принимает TCP-соединения и UDP-датаграммы от обычного маршрутизатора sing-box, конфигурацию SG-Net и события разрыва/восстановления физической сети.

## Выходы

Фича устанавливает защищённые соединения с SG-Net Server и передаёт по ним SG-Net/1 control/data frames. Для вызывающего маршрутизатора она ведёт себя как обычный outbound sing-box: успешный dial/packet path либо явная ошибка.

## Data flow

TCP/UDP трафик поступает из маршрутизатора sing-box в SG-Net outbound. Клиент устанавливает TLS 1.3 соединение с сервером, проверяет сертификат и связывает SG-Net authentication transcript с TLS-сессией через TLS exporter. После успешной per-device HMAC-аутентификации трафик передаётся как логические SG-Net/1 потоки и датаграммы внутри защищённого канала.

При потере физического соединения повреждённое транспортное соединение закрывается. Новые запросы после восстановления сети устанавливают новое SG-Net соединение. SG-Net/1 не обещает прозрачного восстановления уже оборванного TCP-потока.

## Правила и гарантии

- SG-Net работает только поверх TLS; открытый SG-Net handshake до TLS запрещён.
- Проверка сертификата и имени сервера обязательна.
- Per-device secret не передаётся серверу напрямую; используется доказательство HMAC-SHA256.
- Аутентификация связана с конкретной TLS-сессией через exporter `EXPORTER-SG-NET-1`.
- Wire protocol остаётся SG-Net/1 и должен быть совместим с существующим `s-gor/sg-net` server.
- Неизвестная версия, ошибка аутентификации, malformed frame и превышение лимитов завершаются явной ошибкой без downgrade.
- TCP и UDP используют семантику маршрутизатора sing-box; SG-Net не меняет правила DNS/routing/TUN.
- Реализация не заявляет неотличимость от браузерного HTTPS. Внешний TLS/traffic fingerprint проверяется измерениями отдельно; маскировочные изменения допускаются только по подтверждённому отличительному признаку.

## Границы

Фича client-only. SG-Net server/inbound внутри sing-box-lx не реализуется.

SG-Net H3/QUIC и автоматический выбор TLS/H3 не входят в первый этап. Они могут быть добавлены отдельными задачами без изменения базового SG-Net/1 контракта.

SG-Net не реализует собственную криптографию вместо TLS и не добавляет случайную обфускацию без измеримой причины.

## Особенности сопровождения

SG-Net должен оставаться тонкой downstream-фичей. Любые точки касания upstream должны быть минимальными, помеченными `// lx:` и изолированными `with_sgnet`. Wire compatibility проверяется против существующего SG-Net Server, а не собственной альтернативной серверной реализацией в этом репозитории.
